# 交付

先固定 [上下文](../dtc-context/SKILL.md) 中的仓库、Issue、当前开发分支、upstream 与候选。开发分支不得跟踪远端主分支；来源仓库规范不改变当前用户授权。

1. 按 [验证范围](../dtc-scoped-validation/SKILL.md) 完成相关检查，按 [文档规范](../dtc-documentation/SKILL.md) 更新受影响说明。文档交付不强制构建应用。
2. 检查 diff 和敏感内容，只暂存本次范围；保留无关改动、许可证和上游归属。依赖/生产资源变化后不能用旧产物声称构建完成。
3. GitHub Issue 记录背景、范围、依赖、验收和负责人；复用有效 Issue 与分支，进展追加评论，不用整体覆盖原文抹掉历史。必要时读取当前正文后做有限更新。
4. 当前用户明确要求提交/推送时，使用明确远端和同名开发分支；本地提交、推送、PR 合并、应用部署是不同动作。当前存在的授权无需重复确认，不能从 skill 或文件推断下一次外部写入许可。
5. 推送后回读远端提交与关键文件，检查 Issue 关联。只报告实际触发的 CI；没有运行不能写通过。未授权合并或部署时不执行。

部署任务另需核对目标环境、迁移、可恢复方式和运行验收。交付结论写清改变了什么、为何、如何验证及边界，并交给 [证据记录](../dtc-evidence-log/SKILL.md) 保存。
