# 业务功能实现

读取 [项目档案](../../../.dtc/target-profile.md)、当前需求与适用设计，复用 [上下文](../dtc-context/SKILL.md)。源码组织以现有目录为准，不照搬来源仓库的页面、店铺或构建约定。

- 以一条可验收行为为增量：请求校验、业务规则、存储/外部接口、响应和 UI 按实际需要连接。业务规则放服务层，路由不直接混入模型、数据库和外部副作用。
- AI 输出经过 Schema 和业务校验；从服务端身份确定权限；测试使用 Fake Provider/Connector，真实外部写入遵循当前授权。
- 共享行为变化沿真实消费者补回归；数据、模型输出、超时、重复操作和状态竞争按本次影响验证。不为简单功能增加无收益的抽象层。
- UI 改动说明用户看到的加载、无结果、失败、待审批、完成状态与操作权限。没有视觉设计输入时按现有组件保持一致，不虚构 Figma 规格。
- 依赖与配置变化同步 `pyproject.toml`/锁文件、环境模板、使用文档和受影响构建。命令从实际配置核对，不假设本仓是 Nx。
- 稳定复现的缺陷先保留失败证据；不补造修复前 RED。变更后使用 [范围验证](../dtc-scoped-validation/SKILL.md)。

按 [文档规范](../dtc-documentation/SKILL.md) 说明本次行为、关键函数、设计原因和一个可检查例子；更新原主题即可，不为每个函数新建教程。代码、验证和交付状态交给 [交付](../dtc-delivery/SKILL.md)。
