# 故障分析与学习

适用于接口报错、依赖连接失败、模型结果异常、任务卡住和重复业务操作。先读 [项目档案](../../../.dtc/target-profile.md) 与本次实际调用链；这是对通用故障分析方法的项目化重写，不依赖原仓库平台或凭据。

1. 固定出错版本、请求样例、时间、环境和可观察症状。明确什么应当发生、实际发生什么；脱敏后保留最小复现，未知项不填猜测。
2. 沿请求入口 → 服务/规则 → 数据库或模型/外部接口 → 返回结果检查。先确认失败在哪一层，避免把所有异常归因于模型；区分正常与异常样例有什么条件差异。
3. 有证据后提出具体解释，列出支持证据、反证检查和未检查部分。存在合理替代解释时做区分实验；证据不足就保留待查，不为填表虚构第二个原因，也不把相关性当因果。
4. 每次实验写明要区分什么、操作会影响哪里、预期观测与实际结果。先选局部、可逆、无外部写入的验证；外部请求超时不能据此认定未执行。
5. 修复后重放同一失败样例与受影响回归。涉及恢复时核对业务结果、任务状态及回执；进程启动、HTTP 200 或暂未再报错不分别等于任务成功、根因查明或业务恢复。
6. 用 [验证技能](../dtc-scoped-validation/SKILL.md) 选择检查范围，用 [记录技能](../dtc-evidence-log/SKILL.md) 更新同一主题。新发现不覆盖历史失败。

对学习者说明：现象是什么、哪个事实缩小了范围、为什么改这里、如何证明修好、还没有证明什么。重要概念先用工单例子解释，文档遵循 [文档规范](../dtc-documentation/SKILL.md)。

输出：结论及可信边界、已查证据、尚未排除的原因、已验证修复或下一项区分实验。分析和技能本身不扩大改代码、付费调用或生产操作授权。
