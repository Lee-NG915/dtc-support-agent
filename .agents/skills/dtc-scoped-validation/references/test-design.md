# 工程测试与模型评测

从本地技能库的分层测试原则改写。按风险选择，不照搬原仓库的 HTML 报告、私有 CI、固定比例或覆盖率门槛；现有 CI 门槛由仓库配置决定。

| 层次 | 本项目例子 | 能证明什么 |
|---|---|---|
| 单元/契约 | 参数校验、审批过期判断、同键不同参数冲突 | 给定输入下的确定规则 |
| 集成 | 实际数据库约束、事务、迁移和服务调用 | 被测组件协作；SQLite 结果不覆盖 PostgreSQL 特性 |
| 端到端 | 从公开 API 或客服界面查询、审批、创建 Fake 工单 | 声明的环境和替代边界内业务链路成立 |
| 真实试用 | 客服完成任务并记录采用、修改、返工和耗时 | 观察到的用户效果；不能由 Fake 或模型评分代替 |

一个新场景至少写清输入、身份、初始数据、动作、可观察结果及禁止结果。已有验收编号可直接引用，不另建同内容编号体系。

异常测试既检查失败，也检查之后能否按约定继续。例如写入超时后应查询回执，不能只断言返回了错误。跨服务测试从公开入口发起，不用跳过关键审批来模拟成功。

对关键保护逻辑，可在隔离临时副本中制造缺陷或注入异常，确认测试能够捕获；保留前置条件断言，避免根本没进入被测路径。不要在共享工作区破坏代码，不要求每次低风险文案修改做全量故障实验。

模型评测另建固定任务集和判分依据：固定输入、数据、Prompt/模型版本；开发样例用于迭代，保留样例用于最终比较。记录任务成功、引用支持、工具参数、成本和延迟；人工等待单列。两版本对比只使用双方都支持的同一组任务，新功能覆盖单独说明。

首次开发就定义少量样例和预期，不等待算法课程完成。Fake 通过只说明控制流或规则通过，不说明真实模型质量。失败案例保留，不能删掉后宣称提升。
