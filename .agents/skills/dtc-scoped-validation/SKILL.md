# 验证范围

使用 [项目档案](../../../.dtc/target-profile.md) 中真实命令，固定提交/工作区、配置、数据版本与环境。存在测试目录不等于测试已经通过。

| 变更 | 必要验证 |
|---|---|
| 文档或开发技能 | 技能结构、路径/链接、适配依赖和设计一致性；无需启动应用 |
| API/规则/权限 | 正常与无效输入、未认证、越权、直接消费者和错误响应 |
| 数据/任务/审批 | 事务、迁移、并发、重复、过期、重启；涉及 PostgreSQL 语义时使用 PostgreSQL 集成验证 |
| 外部写入 | 超时、外部成功本地失败、稳定幂等键、回执查询、不确定结果转人工 |
| Prompt/检索/模型 | 固定开发集与保留集，控制配置变量，记录业务结果、引用、成本/延迟和失败分类 |
| React UI | 受影响 Vitest、构建及必要浏览器行为；加载/错误/审批状态、可访问性和直接消费者 |
| 部署/依赖 | 干净安装、迁移、健康状态、实际依赖、故障定位与恢复 |

常规工程测试默认不调用收费模型或真实业务写接口。真实模型评测与 Fake 测试分列；自动评分不替代人工复核。小样本展示分子/分母，比较同一集合，新增不支持任务单独报告。评测标准从第一个业务样例建立。

受影响检查通过后停止重复运行；新变更或新失败再扩大范围。skip、未运行、旧版本通过都不能写成本轮通过。参考 [独立审查](references/independent-review.md)，结果由 [证据记录](../dtc-evidence-log/SKILL.md) 保留。

具体测试分层、异常恢复和模型评测口径见 [测试设计参考](references/test-design.md)。遇到无法解释的失败时进入 [故障分析](../dtc-troubleshooting/SKILL.md)。
