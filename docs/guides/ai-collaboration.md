# Codex 方案与验收、Claude 实现协作规范

更新日期：2026-11-06。状态：**用户已确认；本次调整起由当前 Codex 负责文档、方案、测试计划与最终验收，Claude 负责实现及必要的单元测试。**

本规范定义 AI 协作分工，不改变产品需求、技术设计、跨仓契约和用户授权的既有权威来源。此前已经完成的修改、测试和 Review 按当时实际执行者保留历史记录，不因本规范回溯改写。

## 1. 责任分工

### Codex：项目经理与最终验收负责人

Codex 负责管理和决策工作：

- 澄清业务目标、范围、非目标和约束，完善需求文档、产品设计与技术设计。
- 制定开发计划和测试计划，把需求映射到实现任务、测试场景和验收证据。
- 向 Claude 下发边界明确的执行任务，提供权威文档、目标文件、权限和预期产物。
- 审查 Claude 的改动、Review 结论和执行证据，判断采纳、返工或拒绝，不直接照搬。
- 作出最终验收结论，维护权威文档、Issue、里程碑、风险和未验收范围。

Codex 编写需求、设计、计划、验收和协作文档属于项目管理职责。实现与必要的单元测试交给 Claude；Codex 可以读取源码、开展代码 Review，并按测试计划执行验收检查、集成验证或评测，但不静默接管实现。

### Claude：本机执行层

Claude 负责按已确认方案执行：

- 阅读代码和复现问题，实施代码、配置、Schema、fixtures 与测试改动。
- 完成实现所需的调试、必要的单元测试和相关静态检查；额外测试执行范围由 Codex 的测试计划明确。
- 返回实现说明和单元测试证据；发现方案或契约缺口时交回 Codex，不自行改变验收标准。
- 输出实际改动、执行命令、真实结果、失败项和未验证范围，供 Codex 验收。

Claude 不擅自改变需求、产品设计、验收标准或跨仓契约，不把自测或 Review 结论称为最终验收。发现方案缺口、权限不足或结果不确定时，停止相关执行并交回 Codex 决策。

### 用户：需求与外部行为授权

用户确认业务目标、优先级和方案选择。提交、推送、合并、部署、真实外部写入、真实客户数据、付费评测及密钥使用仍按每次实际授权执行；本规范不扩大任何一方的权限。

## 2. 标准工作流

```text
需求/问题
  → Codex 完善需求、设计与验收标准
  → Codex 制定开发计划和测试计划
  → Codex 向 Claude 下发执行任务
  → Claude 实现并执行必要的单元测试，返回 diff 与证据
  → Codex 审查 diff 和证据，决定返工或最终验收
  → Codex 同步权威文档和 Issue
  → 按用户授权执行提交、推送或部署
```

每个执行任务至少说明：

1. 关联 Issue、目标和非目标。
2. 必须遵循的需求、设计、契约和验收条目。
3. 允许修改的范围、禁止操作和秘密/数据边界。
4. 需要完成的实现、必要的单元测试和额外验证范围。
5. 需要返回的文件清单、命令结果、失败记录和未验证范围。

Claude 返回后，Codex 必须检查实际 diff 和证据。测试不足、结论无复现依据或实现偏离设计时，应下发新的修复/验证任务，不能直接验收。

## 3. 最终验收门禁

最终验收由 Codex 签署，至少满足：

- 每项本次需求都有对应实现或可解释的未完成状态。
- 关键正常、异常、权限和恢复场景有测试计划及实际执行证据。
- 测试命令、环境、通过数、失败数和报告位置真实可查，失败历史不被删除或美化。
- Review 发现已逐条裁决；安全、权限、幂等和契约问题不能仅以“简化”为由忽略。
- 计划、实现、已验证、已推送和未验收状态分别记录，不用 Claude 的自评代替项目结论。

验收结论应明确为“通过”“不通过”或“有条件通过”，列出证据和剩余风险。需要补充运行验证时，由 Codex 明确验收范围并自行执行，或向 Claude 下发补充验证任务；Codex 根据实际结果作最终判断。Claude 的单元测试通过不能单独作为最终验收。

## 4. 阻塞与权限边界

- Claude 不可用、额度受限、执行中断或无法复现时，Codex 记录阻塞并交回用户或调整计划，**不得静默接管执行层工作**。
- 双方不得读取或输出 `.env`、API Key、服务 token 和真实客户数据，不得执行未经授权的真实外部写入。
- 提交、推送、合并和部署按用户实际授权执行；2026-11-06 用户已持续授权本项目后续章节在 Review、剃刀检查和验收通过后直接提交、推送并同步文档与 Issue，不再逐章确认。该授权不包含默认合并主分支、生产部署、真实客户数据、真实退款/取消或无上限付费调用。
- 跨仓产品行为仍以 `product-blueprint.md` 为正本，wire schema 仍以 OpenAPI 为正本；Claude 执行报告和 Issue 评论都不是替代正本。
- Codex 的最终验收也不等于用户接受、生产部署或真实业务批准，这些状态必须分别提供证据。
