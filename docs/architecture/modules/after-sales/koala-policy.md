## 1. 政策来源与效力

`knowledge/` 根目录原有中国电商规则是上游演示数据，不能用于 Koala 或 E-pig 的 AU/SG/US 订单。当前新增内容位于：

- `knowledge/koala/au/`：退货、退款、配送、取消/改单、交付损坏/缺件、保修，共 6 份；
- `knowledge/koala/us/`：同样的 6 个售后主题，共 6 份；
- `knowledge/policy-manifest.json`：文档路径、品牌、市场、商品类别、快照日期、来源 URL、来源页面日期，以及冲突章节和查询触发条件的机器可读清单。

所有条目均为 `status: demo`，快照版本为 `snapshot-2026-11-05`。这些文件是根据 Koala 官方 storefront、服务条款和帮助中心整理的中文摘要，**不是 Koala 官方或附属文件，不表示合作、品牌授权、法律意见或生产批准**。处理真实订单前必须复核官方原文、订单适用条款和法定消费者权利。

调研时 `sg.koala.com` 未能建立可验证的现行官方来源，因此没有创建 SG 政策文件，也不得以 AU/US 内容补齐 SG。AU 区域配送价格和时效等无法完整核验的信息同样保持缺失，没有补写推测数字。

## 2. 检索范围与信任边界

每次 Koala 检索都由 `PolicyScope` 限定：

| 字段 | 作用 |
|---|---|
| `brand` | `koala` 与 `upstream_demo` 完全分离 |
| `market` | Koala 必须显式指定 `au`、`us` 或 `sg`；不能使用 `global` |
| `as_of` | 只检索该日期可适用的快照；当前快照之前的历史订单返回无证据，未来日期在校验层拒绝 |
| `product_category` | Koala 必填；限定床垫、家具、家居品或床品，缺省时无证据，US 当前仅覆盖家具 |

范围在 BM25、内存向量、Qdrant、HybridRetriever、Self-RAG 和知识工具之间透传，并在 `top_k` 截断前过滤。缓存键同时包含查询、范围与知识库指纹，避免 AU/US、不同商品或不同知识版本串用结果。

`ChatRequest` 的 `brand`、`market`、`policy_as_of`、`product_category` 是演示和测试入口，**不是生产授权依据**。生产接入时，品牌、市场和订单日期必须由服务端从已验证订单/会话上下文确定，不能信任消费者请求体。Koala 当前轮有意不读取历史消息，防止同一会话切换市场时污染回答；这也是当前增量的多轮对话限制。

未传 `brand/market` 的既有调用仍使用 `upstream_demo/global`，保持上游演示兼容，但 Koala 请求不能回退到这些中国电商规则。

## 3. 回答与工具保护

1. **普通问题**：只有命中匹配品牌、市场、商品和日期的证据时，才可基于证据生成回答并返回来源、快照和范围字段。非社交问题即使被模型路由为 `DIRECT`，也会强制改为检索；生成层保留同样保护，只有问候和闲聊允许直接回答。
2. **无证据**：缺少商品类别、SG、历史日期不适用、商品不受支持或没有召回时，固定说明证据不足并转人工，不套用其他市场条款。未来政策日期属于无效请求，不用当前快照回答未来。
3. **来源冲突**：manifest 的 `review_sections` 只标记具体冲突章节，`review_query_rules` 按冲突主题声明复合条件：每个 `all_of` 组都必须命中，组内词项才是同义备选，避免“最少”“至少”“多久”“配送费”等孤立词直接触发。`policy_review_chunks()` 在全部最终召回文档中选择与查询匹配的冲突证据，不再只看首证据所属文档；若首冲突段严格强于所有非冲突证据，即使释义未命中词表也保守转人工。门控和人工复核引用使用同一组 chunk。正常回答会剔除未触发复核的冲突段，防止模型看到无关冲突后过度拒答。因此，“家具损坏后多久能退款”能跨损坏与退款文档触发复核，而正常配送费支付、退货材料、价格和保养问题不会被无关条款误拦截。
4. **正常期限与配送服务**：普通 120 天退货期限、US White Glove 价格与时效可基于对应正常章节回答；最低试用期、退款时间冲突、Premium Delivery 退款例外和取消资格仍转人工。
5. **正常保修/损坏/缺件**：使用对应主题证据，不因召回列表中混入无关退货冲突文档而一律拒答。损坏、缺件和保修正文本身仍要求结合订单、物流和照片进行人工评估，不自动承诺维修、更换或退款。
6. **工具隔离**：Koala 规划只允许 `search_knowledge`。通用演示优惠券、SKU 保修工具不得回答 Koala；即使消息包含演示订单号及“退货/退款/取消”，也不能触发上游演示写工具。待确认写动作同时绑定 session、user 和完整政策范围，跨品牌、市场、商品或日期不能确认旧动作。
7. **引用一致**：图检索和工具执行路径都恢复完整政策元数据和完整 chunk 正文，不做 400 字截断；引用包含来源 URL、市场、快照及人工复核状态。知识库指纹覆盖引用与复核元数据，避免旧缓存沿用已变化的引用。

当前离线回退重排使用中文词元、标题与正文加权覆盖；它不是 Cross-Encoder。Koala 真实生成使用温度 0，并在提示词中要求保留损坏、错发、缺件问题对应的材料与人工处理下一步。固定 29 条离线集和直接 `generate_node` 真实模型集只能证明这些样例的检索、保护和生成行为，不能证明完整图、Self-RAG/Faithfulness 或所有自然语言问题都不会出错。

## 4. 已显式保留的官方冲突

以下差异写在对应政策正文中，并由 manifest 标记人工复核：

- AU 床垫最低保留 7 天与帮助中心舒适商品至少 14 晚；
- AU/US 污渍或损坏排除与合理磨损可接受、显著损坏不可接受；
- AU 免费取件都会清单是否包含 Canberra；
- AU 退款 3–5 与 5–7 个工作日；
- AU/US 帮助中心发货前取消路径与 Terms 较窄的取消表述；
- US 一般原始配送费可退与 Premium Delivery 明确不可退；
- AU 区域配送价格/时效不完整。

AU 自愿试用/保修不排除 Australian Consumer Law 权利；US 保修和责任限制必须与州法保留语句一起理解。法定权利、重大故障、具体赔偿和责任限制争议均不得由 Agent 一揽子裁决。

## 5. 调用示例

AU 床垫保修：

```json
{
  "message": "床垫保修多少年",
  "user_id": "demo_agent",
  "brand": "koala",
  "market": "au",
  "policy_as_of": "2026-11-05",
  "product_category": "mattress"
}
```

US 家具退货将 `market` 改为 `us`、`product_category` 改为 `furniture`。US 当前没有床垫政策，传 `mattress` 应返回无证据。SG 请求同样返回无证据，而不是借用 AU/US 答案。上述 `user_id` 只是现有演示接口字段，不代表已认证员工身份。

## 6. 更新与发布门禁

1. 人工打开并核对官方原文，记录页面更新日期和实际检索日期；静态检查器不会抓取 URL。
2. 同步更新对应市场正文与 manifest，禁止跨市场复制条款；新增市场前必须有可验证官方来源。
3. 对冲突和例外设置 `requires_human_review`、`review_sections` 和按主题拆分的 `review_query_rules`。用 `all_of` 表达必须同时成立的上下文，只在组内放同义备选，不要把冲突消解成未经确认的单一承诺，也不要用过宽词项拦截无关正常问题。文档路径和官方来源 host 必须与声明市场一致；配置的复核 section 不存在或规则含空白项时，ingestion 必须失败。
4. 更新固定评测，保留失败样例及跨文档、释义和正常问题对抗样例；运行 `scripts/check_koala_policy.py`、政策单元/集成/HTTP 测试、全量测试与 `eval.runner --task koala-policy`。配置真实模型后另运行带 `--llm` 的生成节点评测，分别记录两部分结果。
5. 检查引用、缓存隔离、工具路径、无证据、缺商品类别、未来日期、历史日期、DIRECT 路由和正常问题过度拦截。空语料不得触发 Qdrant 清理；单检索后端异常且另一边为空时必须报错，不能缓存假的“无证据”。
6. 生产使用前另需品牌/业务/法律负责人批准，并以真实订单日期建立历史版本；当前 `demo` 包不能直接标记为生产政策。

检查入口：

```bash
python scripts/check_koala_policy.py
python -m pytest -q tests/unit/test_policy_scope.py tests/integration/test_koala_policy_retrieval.py
python -m eval.runner --task koala-policy
# 以下命令会调用已配置的真实生成模型，不会执行真实外部写入：
python -m eval.runner --task koala-policy --llm
```
